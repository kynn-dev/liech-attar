# Liech evidence register

This register is a compact, non-secret record of the repository evidence used
by `liech-brand-direction`. It is a source map, not a brand book. The paths are
canonical-repository paths and must be rechecked when the product changes.

| Source path | Evidence retained by the skill |
| --- | --- |
| `README.md` | The named context is Liech Parfums; the Hub is an internal operational surface for production, perfume formulation, and CRM. |
| `docs/specs/01-product-vision-and-user-journey.md` | The direction is internal operations first, with a later vertical perfumery product; it is not a generic CRM or ERP. |
| `docs/specs/06-ui-navigation-and-ux-principles.md` | The operational UI is dense and task-oriented, with persistent navigation, tables, KPI cards, kanbans, drawers/modals, theme support, and dark mode as the current primary experience. |
| `docs/specs/06-ui-navigation-and-ux-principles.md` | Important screens should answer what to do now, expose loading/empty/error states, keep entities traceable, and support essential mobile actions. |
| `docs/specs/08-ai-system-overview.md` | Éter separates retrieved facts, inference, hypothesis, sources, and uncertainty; critical changes require human confirmation. |

These summaries are the only claims this package treats as confirmed. Logo,
palette, typography, imagery, public positioning, audience, tagline, and voice
remain `UNKNOWN` unless an approved source is supplied.
